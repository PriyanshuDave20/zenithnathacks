# Communication UI

The `/start` clinician setup, focused patient flow, clinician review/reply, and `/icu` board extend the existing Synapse design system. The latest user direction replaces the shared patient dashboard with clinician-selected language and support, a clear device handoff, and one patient task at a time. The supplied Akash system specification and ASCII wireframe remain visual references. The earlier concept-roll waiver still applies (Zach, 2026-11-07: “waive it”); no new visual world was introduced. `docs/PRODUCT.md` remains the product source of truth. Root `DESIGN.md` and `.impeccable/design.json` are preserved.

## Surface and file boundaries

`src/app/start/page.tsx` mounts `CommunicationWorkspace`; `src/app/icu/page.tsx` mounts `IcuBoard`. Both retain `RequireClinician`. Flow composition, `SessionSetup`, and scoped styles live in `src/components/communication/`. The patient stages reuse `IntakeFree`, `IntakeGuided`, and `ConfirmReadBack` from `src/components/session/patient-screens.tsx`. That existing frontend file has one narrow correction: when speech is unsupported or denied, the visible textarea submits typed text rather than an empty speech transcript. Mocks, backend, contracts, input-channel internals, and shared configuration are unchanged. The existing session API adapter, speech hooks, strings, and body diagram remain the integration points.

The matching surface briefs are `.impeccable/surfaces/src-app-start-page-tsx.md` and `.impeccable/surfaces/src-app-icu-page-tsx.md`.

## Clinician setup and patient flow

The first screen belongs to the clinician. They choose one of the four mock languages and one of five support modes: Speak & translate, Deaf / hard of hearing, Pictures & simple questions, Can’t speak, or Eye selection · ICU. For non-ICU modes they also choose free intake or guided picture questions. Selecting Standard defaults to free intake; selecting another non-ICU mode defaults to guided intake, with the path still editable. ICU is disclosed as an English-only interface preview before handoff.

Optional Display and read-aloud options are collapsed in a details control. They offer 100%, 125%, and 150% text, scoped high contrast, and an eligible Read replies aloud preference. The preference is hidden for Deaf/HoH and ICU. This preference does not disable the existing guided question read buttons or low-literacy/mute body-part speech. The setup grid has two columns on larger screens and stacks at 760px and below, with a sticky Pass to patient action.

Pass to patient opens a full navy handoff screen. A localized “I’m ready” action opens the chosen patient intake; ICU instead links to `/icu`. Back to clinician returns to setup, or to the conversation when a reply is ready. Handoff actions assert who holds the device; they are not authentication or an identity check. The route’s clinician-account gate is separate.

Patients see the existing focused intake screens in their selected language, without the clinician conversation log, composer, language/mode toolbar, or summary. The shared header retains the holder label and Clear. Free intake supports browser speech recognition with a visible transcript and typed fallback; Can’t speak also provides existing phrase chips and speak-for-me. Guided intake presents one existing question at a time, with pictures or body-region selection, duration and other choices, and the unchanged five-choice 1–5 intensity scale. It does not use the former workspace’s extra 0–10 pain control or add a new severity contract field.

Submission opens the existing localized read-back screen. The patient confirms the meaning or returns to intake to try again. Only confirmation adds a translated patient turn. A request failure offers retry or a handoff of the patient’s own untranslated words; it must not imply that translation succeeded. Returning to free intake restores submitted text; guided choices use the existing component’s local state and restart when the screen remounts.

Confirmation opens a navy Pass to clinician screen. The clinical summary remains unrendered until “I’m the clinician” opens review. The localized Back action returns to patient intake, or to teach-back after a reply. After clinician review, Ask the patient for more details returns through the patient-ready handoff to focused intake; Change language or mode returns to clinician setup.

## Clinician review and reply

Review shows a patient recap beside a navy clinician summary. The summary presents the latest translated chief complaint and duration, symptoms and flags across confirmed translated turns, original text, translated text, and low-confidence reasons. Untranslated fallback turns are identified separately. Missing values remain “Not stated.” Copy communication summary uses the browser clipboard only when requested and asks the clinician to review it before adding it to a record. No vitals, assessment, diagnoses, medications, or orders are generated; clinical decisions remain with the clinician.

Reply to patient opens the clinician conversation workspace. Its log and composer share a wide-screen split (1.4:1) and stack at 1000px and below. The log preserves patient and clinician turns in opposing tailed bubbles with original and translated text. Flip view rotates only the log. The clinician can type, use supported browser speech recognition, or select a supplied reply. Space toggles the workspace microphone only outside editable or interactive controls when voice input is active. Speaker-switch controls are hidden; the primary flow sets the holder through handoffs.

The conversation workspace and its accessibility toolbar/footer are guarded by clinician role. The toolbar appears only during clinician conversation and summary stages. On smaller screens it collapses into a persistent mode/text-size row with a Change control; expanded contents scroll within a bounded area. It provides the four non-ICU support modes, text sizes, high contrast, and eligible Read replies aloud preference. Language controls and interpreter guidance stay in the clinician workspace. Context changes are disabled during work or a pending confirmation.

Sending a clinician reply uses the unchanged mock response path, then opens the patient-ready handoff. The patient continues to the reply and localized teach-back choices. Yes, no, or unsure is recorded against the latest reply, then the device returns through Pass to clinician to review. A prepared reply can also be reopened through Pass to patient · teach-back from summary.

## Demo limits and fallback behavior

Only the four existing mock languages are exposed: English (`en`), Spanish (`es`), Arabic (`ar`), and Simplified Chinese (`zh-Hans`). The mock data and translation/reply behavior are unchanged. Keyword summaries and supplied reply translations demonstrate the interaction; they are not a full translation service. Replies outside the mock’s supported examples remain in English with an unavailable-translation notice. A fluent speaker’s review and a qualified interpreter remain necessary where appropriate.

The interpreter action opens guidance to contact the clinic’s service or staff; Synapse does not place a call or notify anyone. Deaf/HoH hides eligible read-aloud controls and enlarges conversation captions. Its clinician-workspace door-knock notice is an explicitly manual demo cue, not ambient sound detection. Pictures/AAC is the existing limited pictogram/phrase vocabulary, not a complete AAC system. No developer inspector or device-preview controls are included in patient intake; ICU visibly identifies its input limitation.

The clinician composer preserves its draft on failure and offers retry, typing, or interpreter help. Patient read-back failure retains submitted inputs for retry or untranslated handoff. Speech recognition and synthesis depend on browser support; text remains available. Main patient content uses the existing localized strings. Patient-language blocks carry `lang` and `dir`; Arabic uses right-to-left direction while English clinician chrome and handoff explanations retain their own direction. ICU remains English-only.

## Memory and clearing

Conversation, submitted patient inputs, pending read-back, drafts, selections, and summaries are React/browser memory only; there is no patient persistence. Clear and End use a two-step confirmation. Clearing invalidates outstanding patient-translation and clinician-reply requests so a late response cannot repopulate the conversation, stops recognition, and cancels speech synthesis. Clear returns to clinician setup; End opens the Session cleared state. Starting again returns to setup. Display and language/mode preferences can remain while conversation content is removed.

The workspace also invalidates work, wipes conversation content, and resets to setup when the route is hidden/unmounted, on `pagehide`, and on a persisted `pageshow` restoration. Its idle timer warns 30 seconds before the clinician's chosen session timeout (10 min, 30 min, 1 h, 2 h or 6 h; default 6 h, set on the dashboard, `src/lib/session-timeout.ts`, kept in this device's localStorage), offers Keep session, and clears at the timeout without activity (it was 4:30 and 5:00 until 2026-11-08). It runs in active stages and also in setup if turns, submitted patient inputs, or a draft remain; empty setup and the cleared state do not run it. These protections do not make the UI an authentication boundary. Clipboard text explicitly copied by the clinician is outside the app’s in-memory clearing behavior.

## ICU preview and integration boundary

ICU is one of the five initial setup modes and opens through the patient-ready handoff. `IcuBoard` displays six English choices: Yes, No, Pain, Help, Move me, and Take a break. Native buttons support touch/mouse and keyboard activation. Selection appears with a check, a Selected label, `aria-pressed`, and a polite “You chose” status message above the choices. The board uses three columns on larger screens and two on phones. Compact phone targets keep all six choices within reach in the 390px bedside viewport; explanatory hints are hidden there while icons and labels remain.

Clinician guidance & preview controls is a closed details section below the board, rather than a competing guidance panel. It contains positioning advice, the input-integration limit, and Clear preview choice. Pass to clinician hides the board behind a navy handoff; “I’m the clinician” opens a local clinician review of the selected message. Return to patient’s board reopens the board; Finish ICU preview returns to `/start` setup. Back to the board on the handoff also returns to the local board. No ICU choice is transferred to a conversation or summary.

This is a frontend preview only: no camera is accessed and no calibration, gaze detection, gaze processing, or automatic dwell selection runs. Hover or focus fills a decorative progress bar but never activates a target. Choices do not notify staff, request assistance, or trigger clinical actions. Selection remains in local React state and is cleared on component cleanup; no selections are stored.

The presentation boundary is `IcuBoard({ onSelect? })`, where `onSelect` accepts the existing `SelectEvent` contract. Manual button activation currently emits `{ channel: "tap", optionId }`, including native keyboard activation. The `/icu` route supplies no callback, so this event is not connected to backend behavior. The input-channel team can wire the callback and a real input source later; this preview must never fabricate a gaze event.

## Visual and motion implementation

The surfaces retain the incumbent navy, light blue, white, and cool-blue palette; Figtree headings; Noto Sans body/interface text; Arabic and Chinese font support; pill controls; soft panels; and speaker-side bubble tails in clinician conversation. Default workspace text starts at 16px and can be increased by the accessibility scale; focused patient buttons, labels, and paragraphs start at 18px. Setup choices use 20px corners, workspace panels use 28px corners, bubbles use 30px corners with an 8px tail, and actions remain at least 44px tall. The setup handoff action is 56px tall. These are local implementation details, not changes to shared design tokens.

Black with yellow (`#ffea00`) is an explicit user-requested accessibility override scoped to these communication surfaces. It does not redefine the global navy/light-blue identity. Selection uses labels/checks or borders alongside color. Focus has a visible outline. Motion is supplementary: message arrivals, selected picture feedback, decorative voice bars, and an ECG-shaped busy indicator. The busy indicator is a loading symbol, not a vital reading. Reduced-motion media queries remove these animations and press transforms; text and states stay visible.

The shared `DESIGN.md` includes earlier staged-session descriptions and component anatomy. Current surfaces reuse focused patient components and the full-screen hand-back pattern while adding clinician setup, dual-summary review, a clinician-only conversation workspace, and first-class ICU selection. Treat this document and the surface briefs as the current page-specific record; a future coordinated system-document refresh can reconcile remaining differences without changing the global identity.
